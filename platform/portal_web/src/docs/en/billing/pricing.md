# Billing & Pricing

DeepPool uses a **pay-per-use** billing model, charging based on the actual number of tokens consumed per API call. This guide explains the pricing strategy, token types, Cached Tokens discount, and how to check model pricing and usage details.

## Billing Overview

Each API call incurs costs from two components:

| Component | Description |
|-----------|-------------|
| **Input Cost** | Based on prompt tokens sent to the model (system, user, assistant context messages) |
| **Output Cost** | Based on completion tokens generated by the model (including reasoning/thinking tokens) |

> **Unit**: All prices are in **yuan per million tokens**.

---

## Token Types

The `usage` field in API responses contains detailed token statistics, fully compatible with the OpenAI standard format:

```json
"usage": {
  "prompt_tokens": 33,
  "completion_tokens": 196,
  "total_tokens": 229,
  "prompt_tokens_details": {
    "cached_tokens": 0,
    "audio_tokens": 0
  },
  "completion_tokens_details": {
    "reasoning_tokens": 7,
    "audio_tokens": 0,
    "accepted_prediction_tokens": 0,
    "rejected_prediction_tokens": 0
  }
}
```

### Field Descriptions

| Field | Description |
|-------|-------------|
| `prompt_tokens` | Total input tokens for this request |
| `completion_tokens` | Total output tokens generated (including reasoning tokens) |
| `total_tokens` | Sum of input + output |
| `prompt_tokens_details.cached_tokens` | Input tokens served from context cache (discounted rate) |
| `prompt_tokens_details.audio_tokens` | Audio input tokens (reserved field, currently 0) |
| `completion_tokens_details.reasoning_tokens` | Tokens consumed during model thinking/reasoning phase |
| `completion_tokens_details.audio_tokens` | Audio output tokens (reserved field, currently 0) |

## Cached Tokens Discount

### What are Cached Tokens?

When your request contains the same context prefix as a previous request (e.g., repeated system prompts, unchanged history in multi-turn conversations), some models can hit context cache. Cached tokens are billed at a significantly discounted rate.

### Pricing Rates

| Token Type | Billing Rate | Description |
|-----------|-------------|-------------|
| Regular Prompt Tokens | **100%** | Non-cached input tokens, billed at the model's standard input price |
| Cached Tokens | **20%** | Cache-hit input tokens, billed at **20%** of the standard input price |
| Completion Tokens | **100%** | Output tokens, billed at the model's standard output price |

### Billing Formula

```
input_cost  = (prompt_tokens - cached_tokens) × input_price / 1,000,000
            + cached_tokens × input_price × 0.2 / 1,000,000

output_cost = completion_tokens × output_price / 1,000,000

total_cost  = input_cost + output_cost
```

### Billing Example

Assume a model with input price **6 yuan/million tokens** and output price **12 yuan/million tokens**:

| Scenario | prompt_tokens | cached_tokens | completion_tokens | Calculation | Total Cost |
|----------|:---:|:---:|:---:|------|:---:|
| No cache | 10,000 | 0 | 5,000 | (10000×6 + 5000×12) / 1M | 0.12 yuan |
| 50% cached | 10,000 | 5,000 | 5,000 | (5000×6 + 5000×6×0.2 + 5000×12) / 1M | 0.096 yuan |
| Fully cached | 10,000 | 10,000 | 5,000 | (10000×6×0.2 + 5000×12) / 1M | 0.072 yuan |

> **💡 Tip**: Caching takes effect automatically — no configuration needed. When the model doesn't support caching or no cache is hit, `cached_tokens` is 0 and billing falls back to the standard formula.

## Tiered Pricing

DeepPool supports **tiered pricing** — the same model may have different unit prices depending on the input token count of a single request:

| Model Example | Input Token Range | Input Price (yuan/M tokens) | Output Price (yuan/M tokens) |
|--------------|:---:|:---:|:---:|
| glm5.1 | 0 < Token ≤ 32K | 6 | 12 |
| glm5.1 | 32K < Token ≤ 80K | 7 | 18 |
| glm5.1 | 80K < Token ≤ 200K | 8 | 20 |

The system automatically matches the applicable price tier based on the `prompt_tokens` count of each request.

## How to Check Model Pricing

You can view each model's pricing on the DeepPool platform under the **"Data"** menu:

1. Log in to the DeepPool platform
2. Click **"Data"** (数据) in the top navigation bar
3. Switch to the **"Billing Info"** (计费说明) tab
4. The page displays pricing information for all models, including:
   - Model name, parameter scale, context length
   - Input token ranges for each tier
   - Corresponding input and output unit prices (yuan per million tokens)

---

## How to Check Usage Details

Under the **"Data"** menu, you can also view detailed API consumption records:

1. Click **"Data"** (数据) in the top navigation bar
2. Switch to the **"API Usage"** (API 消耗) tab
3. The page shows daily aggregated consumption data, including:
   - Total tokens consumed / total requests
   - Daily breakdown by date and model
   - Cost amount for each record

You can filter by time range or model name to track consumption for specific periods or models.

## Free Token Grants & Discounts

- **Free Token Grants**: New users and special promotions may provide free token grants, which are consumed before wallet balance
- **Discount Policy**: Some users may have discount rates applied after free grants are exhausted, before wallet deduction

> Free grant balance and discount information can be viewed on the "Data" page or in your account settings.

## FAQ

### How are Cached Tokens generated?

When consecutive requests share the same content prefix (e.g., a fixed system prompt or unchanged history in multi-turn conversations), the model automatically hits context cache. This is handled automatically by the model — no manual configuration required.

### Why doesn't my request have Cached Tokens?

Possible reasons:
- It's the first request in the session (no prior cache to hit)
- The context prefix differs from previous requests
- The model being used doesn't support context caching

### How are reasoning_tokens billed?

`reasoning_tokens` are a subset of `completion_tokens` (not billed separately) — they are already included in the `completion_tokens` total and billed at the output price.

### How are Hybrid models billed?

Hybrid models intelligently route to the most suitable child model. Billing is based on the actual child model's pricing. You can see which model was used and the corresponding cost in your usage details.
