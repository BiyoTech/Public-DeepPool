# 安全护栏使用指南

安全护栏（Guardrails）是附加到 API Key 上的内容安全规则。每个通过该 Key 的请求（输入）或响应（输出）都会被 LLM 评估器自动评估。根据规则配置，被标记的内容可以被**拦截**（请求返回 HTTP 400）或仅**记录**（不阻断，仅做审计记录）。

## 核心概念

| 概念 | 说明 |
|------|------|
| **阶段（Phase）** | 评估执行的时机：**输入（Input）** — 请求到达模型之前；**输出（Output）** — 模型响应之后 |
| **动作（Action）** | 内容被标记后的行为：**拦截（Block）** — 拒绝请求/响应；**记录（Log）** — 仅记录，不阻断 |
| **评估模型** | 用于内容评估的 LLM 模型（如 GPT-4o、Qwen 等） |
| **评估 API Key** | 用于认证评估器 LLM 调用的 API Key |
| **存储方式** | 评估结果的存储位置：**内置（Builtin）** — 平台托管数据库；**外部（External）** — 用户自建数据库 |

### 输入护栏 vs 输出护栏

- **输入护栏**在用户消息*发送到目标模型之前*进行检查。适用于阻止 PII 泄露、越狱攻击或不安全的提示词。
- **输出护栏**在模型*生成响应之后*进行检查。适用于检测幻觉（虚构事实）、不安全的生成内容或响应中的 PII。

> **注意：** 当启用输出护栏时，流式响应会自动降级为非流式。响应头 `X-DP-Stream-Downgraded: output-guardrail` 会被设置以通知客户端。

### 拦截 vs 记录

| 动作 | 行为 |
|------|------|
| **拦截（Block）** | 被标记的内容将被拒绝。输入阶段 → 返回 HTTP 400 `content_policy_violation`；输出阶段 → 响应被替换为错误信息。评估器自身调用失败时，请求同样被拦截（失败即关闭）。 |
| **记录（Log）** | 被标记的内容会记录在评估结果表中，但请求正常放行。评估器调用失败时，请求照常通过（失败即放行）。 |

## 内置模板

DeepPool 提供 5 个开箱即用的护栏模板。创建规则时选择模板可自动填充名称、阶段和评估提示词。

| 模板 | 阶段 | 说明 |
|------|------|------|
| **PII 脱敏** | 输入 & 输出 | 检测个人身份信息（姓名、邮箱、电话、身份证号、信用卡号、地址）并提供脱敏占位符版本 |
| **PII 屏蔽** | 输入 | 零容忍 PII 策略 — 拦截任何包含个人信息的内容 |
| **不安全内容** | 输入 & 输出 | 检测仇恨言论、骚扰、暴力、自残、色情内容、极端主义和危险指令 |
| **越狱检测** | 输入 | 检测提示注入、指令覆盖、编码混淆、角色扮演利用和系统提示提取尝试 |
| **幻觉检测** | 输出 | 检测虚构事实、伪造引用、关于真实实体的虚假声明和无法验证的自信断言 |

你也可以编写完全自定义的评估提示词。在提示词中使用 `{{content}}` 占位符 — 运行时会被替换为实际待评估的文本。

## 创建护栏规则

1. 导航到 **API Key** 标签页 → 点击一个 API Key 打开详情视图
2. 切换到 **Guardrails 护栏** 标签页
3. 点击右上角的 **+ 添加** 按钮
4. 填写表单：

| 字段 | 说明 |
|------|------|
| **模板** | 可选。选择内置模板自动填充字段，或选择"自定义"从零开始编写 |
| **名称** | 规则的描述性名称（如"拦截请求中的 PII"） |
| **阶段** | 选择 **输入（Input）** 或 **输出（Output）** |
| **动作** | 选择 **拦截（Block）** 或 **记录（Log）** |
| **评估模型** | 选择用于评估内容的 LLM 模型 |
| **评估 API Key** | 选择用于认证评估器调用的 API Key |
| **评估提示词** | 发送给评估 LLM 的提示词。使用 `{{content}}` 作为待评估文本的占位符 |
| **结果存储** | **内置（Builtin）** — 平台托管数据库；**外部（External）** — 用户自建数据库（需填写连接信息） |

5. 点击 **保存** 创建规则

规则创建后**默认启用**。你可以在规则列表中直接切换启用/禁用状态，无需删除规则。

## 管理规则

在 API Key 详情视图的 Guardrails 标签页中：

- **切换** — 点击启用/禁用标签快速切换规则状态，无需删除
- **编辑** — 鼠标悬停在规则上，点击编辑图标修改任意字段
- **删除** — 鼠标悬停在规则上，点击删除图标（需确认）

一个 API Key 可以附加多条规则。所有匹配阶段的已启用规则会在每次请求时**并行评估**。

## 查看评估记录

在 Guardrails 标签页内切换到**评估记录**子标签页，查看所有评估日志：

| 列 | 说明 |
|----|------|
| **时间** | 评估执行时间（UTC） |
| **Request ID** | 唯一请求标识符（点击可复制） |
| **阶段** | 输入或输出 |
| **已标记** | 评估器是否标记了该内容 |
| **置信度** | 评估器的置信度评分（0–100%） |
| **已拦截** | 请求/响应是否被实际拦截 |
| **耗时** | 评估耗时（毫秒） |
| **原因** | 评估器对其判断的解释说明 |

### 筛选

使用顶部的**日期范围选择器**按时间段筛选结果，然后点击**搜索**。

结果列表采用**无限滚动加载** — 向下滚动即可加载更多记录。

## 最佳实践

1. **输入用拦截，输出先记录** — 建议先对输出护栏使用"记录"模式，了解流量模式后再启用拦截。
2. **选择快速的评估模型** — 护栏评估会增加每次请求的延迟。使用小型快速模型（如 GPT-4o-mini）可降低开销。
3. **无需担心评估器递归** — 评估器 API Key 自身的请求会被自动排除在护栏评估之外（通过 `X-DP-Guardrail-Eval` 请求头），防止无限循环。
4. **组合多层护栏** — 将输入端的 PII 拦截与输出端的幻觉检测结合，实现全方位覆盖。
5. **定期查看评估记录** — 定期审查记录结果，调优评估提示词，减少误报。
