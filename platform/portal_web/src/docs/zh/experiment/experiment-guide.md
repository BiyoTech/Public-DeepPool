# 评估分析使用指南

评估分析（Experiment）模块提供了一套完整的模型推理质量监控与评估工具链，帮助你追踪推理日志、进行人工标注、以及使用 AI 自动评测模型输出质量。

## 模块概览

评估分析模块包含三个核心子功能：

| 功能 | 说明 |
|------|------|
| **总览（Overview）** | 一站式查看 Trace 追踪状态、Judge 评测任务汇总 |
| **追踪（Trace）** | 创建追踪任务，捕获指定 API Key 和模型的完整推理日志 |
| **AI 评测（Judge）** | 创建 AI 评测任务，使用 LLM 自动评估追踪日志的输出质量 |

进入评估分析模块后，左侧导航栏可在各子功能之间切换。

## 总览（Overview）

总览页面提供三个维度的数据概览：

### Trace 概览

展示当前追踪相关的统计信息：

- **API Keys**：总数量 / 已被追踪的数量
- **Models**：总模型数（含网关模型和自定义模型）/ 已被追踪的模型数
- **Traces**：追踪任务总数 / 运行中 / 已停止

### Judge 概览

以表格形式展示所有评测任务的汇总信息，包括：

- 评测名称、使用的评测模型、评分器类型
- 评测目标（全部日志 / 指定 Trace / 指定模型 / 指定 API Key）
- 当前状态（Pending / Running / Completed / Failed）
- 最近一次运行的通过率

### Evaluation（即将推出）

基于标准测试集的模型基准评测功能，敬请期待。

## 追踪（Trace）

Trace 功能用于捕获模型推理的完整请求和响应日志，是后续评测和分析的数据基础。

### 创建追踪任务

1. 进入 **Trace** 页面，点击右上角 **创建 Trace** 按钮
2. 填写以下信息：

| 字段 | 说明 |
|------|------|
| **任务名称** | 为追踪任务起一个描述性名称，如"GPT4o 质量追踪" |
| **选择 API Keys** | 勾选需要追踪的 API Key（至少选择一个） |
| **追踪模型** | 可选。留空表示追踪所选 API Key 的所有模型请求；也可搜索并选择特定模型 |
| **日志存储** | 选择日志存储方式（见下方说明） |

3. 点击 **创建** 完成

### 日志存储方式

| 存储方式 | 说明 |
|----------|------|
| **内置引擎** | 零配置，使用平台托管的数据库存储日志 |
| **外部数据库** | 连接你自己的数据库（支持 MySQL、PostgreSQL、ClickHouse 等） |

选择外部数据库时，需要填写数据库连接信息（主机、端口、用户名、密码、数据库名），并可点击 **测试连接** 验证连通性。

### 管理追踪任务

每个追踪任务卡片上提供以下操作：

- **查看日志**：进入日志列表页面，查看已捕获的推理日志
- **编辑**：修改追踪任务配置（仅停止状态可编辑）
- **启动 / 停止**：控制追踪任务的运行状态
- **删除**：删除追踪任务（不可恢复）

> **提示**：追踪任务启动后，所有匹配的推理请求都会被自动记录。建议在不需要时及时停止，避免产生过多日志数据。

### 查看追踪日志

点击追踪任务的 **查看日志** 按钮进入日志列表页面：

#### 搜索过滤

支持按以下条件筛选日志：

- **模型名称**：按模型过滤
- **API Key ID**：按 API Key 过滤
- **Request ID**：精确查找某次请求
- **时间范围**：按起止时间过滤

#### 日志列表

列表展示每条日志的关键信息：

| 列 | 说明 |
|----|------|
| Request ID | 请求唯一标识 |
| User Query | 用户输入的问题（截断显示） |
| Model | 使用的模型名称 |
| Tokens | 总 Token 消耗 |
| Duration | 请求耗时 |
| Status | 成功 / 失败 |
| Feedback | 人工反馈状态（通过 / 未通过 / 无） |
| Expectation | 是否设置了期望输出 |

点击任意一行可打开 **日志详情弹窗**。

### 日志详情

日志详情弹窗分为三个区域：

#### 左侧 — 元数据面板

展示请求的基本信息：

- Request ID、模型名称、API Key ID
- 流式 / 非流式标识
- TTFT（首 Token 时间）
- Token 用量明细（Prompt / Completion / Total / Reasoning）
- 请求耗时
- 请求参数（temperature、top_p 等）
- Tools 定义列表
- 错误信息（如果请求失败）

#### 中间 — 请求 / 响应内容

提供两种查看模式：

- **Pretty 模式**：以对话气泡形式展示消息，清晰区分 system / user / assistant / tool 角色，支持 Function Call 和 Reasoning Content 的结构化展示
- **JSON 模式**：展示原始 JSON 数据，方便调试

可通过顶部 Tab 在 **Request**（请求）和 **Response**（响应）之间切换。

#### 右侧 — 评估面板（Evaluation）

用于对日志进行人工标注，包含两部分：

**1. Feedback（反馈）**

为日志添加多维度的质量反馈：

- 点击 **添加反馈** 创建新的反馈项
- 每个反馈项包含：
  - **名称**：反馈维度名称（如"回答质量"、"格式正确性"）
  - **通过 / 未通过**：切换评估结果
  - **原因**：可选，填写评估理由
- 支持添加多个反馈项，覆盖不同评估维度
- 点击反馈项右上角的 × 可删除

**2. Expectation（期望输出）**

为日志设置标准答案或期望输出：

- 点击 **添加期望** 创建期望输出
- 包含以下字段：
  - **名称**：期望项名称（如"标准答案"）
  - **数据类型**：Text / Number / Boolean / JSON
  - **内容**：期望的输出内容
  - **原因**：可选，说明为什么这是期望输出

> **提示**：设置的期望输出可以在 AI Judge 评测中作为 `{{expectations}}` 变量引用，让 AI 评测时参考标准答案。

完成标注后，点击底部 **保存** 按钮提交。

## AI 评测（Judge）

Judge 功能使用 LLM 模型自动评估追踪日志的输出质量，支持批量评测和多种评分策略。

### 创建评测任务

1. 进入 **AI Judge** 页面，点击右上角 **创建 Judge** 按钮
2. 在右侧抽屉中填写以下信息：

#### 基本信息

| 字段 | 说明 |
|------|------|
| **评测名称** | 为评测任务起一个描述性名称 |

#### 评测目标

评测目标决定了哪些日志会被评测，支持逐级筛选：

**第一步：选择 Trace 任务（可选）**
- 选择"所有 Trace"表示不限定追踪任务
- 选择特定 Trace 任务后，可进一步按模型和 API Key 筛选

**第二步：按模型 / API Key 过滤（可选）**
- 当选择了特定 Trace 后，会显示该 Trace 关联的模型和 API Key
- 点击标签可切换选中 / 取消，支持多选

**第三步：选择特定日志（可选）**
- 点击 **选择特定日志** 打开日志选择弹窗
- 在弹窗中勾选需要评测的具体日志条目
- 支持全选 / 取消全选

底部会显示当前评测目标的摘要，如"目标：Trace #1 的所有日志"或"目标：3 条特定日志"。

#### 评测模型与 API Key

| 字段 | 说明 |
|------|------|
| **评测模型** | 选择用于执行评测的 LLM 模型（搜索下拉选择） |
| **评测 API Key** | 选择调用评测模型时使用的 API Key |

#### 评分器配置

**评分器类型**：

| 类型 | 说明 |
|------|------|
| **内置评分器** | 平台预置的评分策略，选择后会自动填充评测 Prompt |
| **自定义评分器** | 完全自定义评测 Prompt |

**评测 Prompt**：

无论选择哪种评分器类型，都可以编辑评测 Prompt。Prompt 中支持以下变量：

| 变量 | 说明 |
|------|------|
| `{{inputs}}` | 用户的输入内容 |
| `{{outputs}}` | 模型的输出内容 |
| `{{conversations}}` | 完整的对话上下文 |
| `{{expectations}}` | 人工标注的期望输出（如果有） |

3. 点击 **创建** 完成

### 管理评测任务

每个评测任务卡片上提供以下操作：

- **运行**：启动评测，对所有匹配的日志执行 AI 评测
- **编辑**：修改评测任务配置
- **查看运行记录**：查看历史运行记录和评测结果
- **删除**：删除评测任务

### 运行评测

点击 **运行** 按钮后，系统会：

1. 根据评测目标筛选出匹配的追踪日志
2. 对每条日志，将其内容填充到评测 Prompt 的变量中
3. 调用评测模型进行评估
4. 记录每条日志的评测结果（通过 / 未通过 + 原因）

### 查看运行记录

点击 **查看运行记录** 打开右侧抽屉：

#### 运行列表

展示所有历史运行记录，每条记录包含：

- 运行编号（Run #ID）
- 状态（Pending / Running / Completed / Failed）
- 进度条（已完成 / 总数）
- 通过率（仅已完成的运行显示）
- 创建时间

通过率颜色编码：
- 🟢 ≥ 80%：绿色
- 🟡 ≥ 50%：橙色
- 🔴 < 50%：红色

#### 评测结果

点击某次运行记录，查看详细的逐条评测结果：

| 列 | 说明 |
|----|------|
| Log ID | 被评测的日志 ID |
| Passed | 通过 / 未通过 |
| Reason | AI 给出的评测理由（点击可展开全文） |
| Duration | 单条评测耗时 |
| Status | 评测执行状态（成功 / 失败） |

## 最佳实践

### 推荐工作流

```
创建 API Key → 创建 Trace 追踪 → 使用 API 产生推理日志
    → 查看日志 & 人工标注 → 创建 Judge 评测 → 运行评测 → 分析结果
```

### 建议

1. **先小范围追踪**：建议先选择特定模型和 API Key 进行追踪，避免日志量过大
2. **善用人工标注**：对关键日志添加 Feedback 和 Expectation，为 AI 评测提供参考标准
3. **迭代优化 Prompt**：根据评测结果调整评测 Prompt，提高评测准确性
4. **定期运行评测**：在模型或 Prompt 调整后重新运行评测，对比前后质量变化
5. **关注低通过率**：重点分析通过率低于 50% 的评测任务，定位质量问题
